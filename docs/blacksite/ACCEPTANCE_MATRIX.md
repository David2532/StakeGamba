## Evidence boundary

This is the project-specific acceptance matrix required before further release work. It complements, and does not replace, the immutable [51-point Stake checklist](STAKE_REQUIREMENTS_51.md) and its machine-readable [candidate evidence map](RELEASE_EVIDENCE_51.json). The pending map binds that canonical checklist by SHA-256 `8e8f3dcc771cfd8668d9fc5bb6e58066df3ead4ea0b2645dd2622b01705fdd04`; this source binding is implemented but is not exact-candidate evidence until the complete resolver chain runs for one immutable candidate.

The exact-green baseline above passed frozen install, lint, production typecheck, 204 app tests, production build, 7 math gates over 300,000 books, isolated package generation/readback, 93 Chromium scenarios with 3,035 checks, and then-current 51-point evidence resolution. It includes the bounded boot intro and compact Vaultkeeper request omission, but predates the pending symbol, player-state, URL-policy, axe, performance, security-evidence and dependency work. Those results are historical regression evidence, not proof for the pending candidate. A row can become release-pass only after the same clean HEAD is committed, packaged and verified by exact CI.

Status meanings:

- `PASS_EXACT_BASELINE` — passed for `c4eeb96b…`; materially affected pending changes still require an exact rerun.
- `IMPLEMENTED_PENDING_EXACT` — implementation is assigned to the pending candidate, but exact-package candidate evidence is absent.
- `PARTIAL` — meaningful proof exists, but at least one repository, manual or external acceptance condition is open.
- `OPEN_REPOSITORY` — implementation or reproducible evidence remains repository-owned work.
- `OPEN_MANUAL` — requires a human, assistive-technology, listening, visual or real-device review.
- `OPEN_EXTERNAL` — depends on production-equivalent infrastructure, Stake/ACP/Slack or an authorized environment.
- `NOT_APPLICABLE` — excluded by the versioned product contract and supported by an executable absence proof.

## Promotion rule

BLACKSITE cannot report `COMPLETE`, `CANDIDATE_GENERATED`, `MANUAL_REVIEW_REQUIRED`, `STAKE_REVIEW_PENDING`, `APPROVED` or `RELEASED` from this matrix. Promotion requires one clean final HEAD whose frozen install, lint, typecheck, tests, build, math, package/readback, exact-package Chromium and 51-point resolver all pass; current screenshots then need manual visual/accessibility/listening/device review, followed by the explicitly external scale, Stake and publication evidence. Unknown, not run, historical-only or assumed evidence remains unpassed.
